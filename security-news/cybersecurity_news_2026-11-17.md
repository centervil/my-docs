# 2026年11月17日 サイバーセキュリティニュースまとめ

## 主要ポイント
*  楽天証券は11月17日、同社のテスト環境への第三者による不正アクセスを受け、顧客情報が外部に漏えいした可能性があると発表しました。部店・お客様コードとログインIDが最大約1,125万口座、氏名・住所・出金先銀行口座・年収や金融資産などを含む情報が最大約447万口座に上ります。ログインに必要なパスワードや暗証番号の漏えい、および本件に起因する不正アクセス・不正取引は、発表時点で確認されていません。
*  ウェブサイト最適化サービス「Optimizely」のアカウント登録処理の脆弱性が悪用され、BBC、CNN、Zoom、HSBC、GitLabなど178の組織のウェブサイトに悪意あるJavaScriptが混入しました。訪問者の暗号資産ウォレットアドレスの書き換え、クレジットカード情報のスキミング、iPhone向けエクスプロイトキットの配信が確認されています。Optimizelyは脆弱性を修正し、混入したコードを除去したとしています。
*  OpenJDKおよびOracle Java SEの重大なリモートコード実行（RCE）脆弱性「Java4Shell」（CVE-2026-114938）の技術詳細が11月17日に公開されました。Base64デコーダーのメモリ破壊により、未認証・ユーザー介在なしでコード実行が可能とされ、Jira、Confluence、Jenkins、Keycloakなど主要製品で認証前RCEが確認されています。Oracleは同日のクリティカルパッチアップデートで修正版を提供しました。

## 楽天証券のテスト環境から顧客情報漏えいのおそれ、最大約1,125万口座
楽天証券は11月17日、同社の一部システムが第三者の不正アクセスを受け、顧客の情報が外部に漏えいした可能性があると発表しました。漏えいしたおそれがあるのは、開発や検証に使う「テスト環境」のシステムで管理していた情報です。同社は11月16日に不正アクセスの可能性を検知し、該当箇所へのアクセスを遮断して修正しました。調査の結果、11月11日にテスト環境で管理していた情報の一部が外部に漏えいしたおそれがあることが分かりました。対象は、部店・お客様コードとログインIDが最大約1,125万口座、氏名、カナ氏名、生年月日、住所、電話番号、メールアドレス、勤務先、出金先口座（金融機関・口座番号・名義人）、年収・金融資産（本人の申告）、商品別資産情報、最終ログイン日などが最大約447万口座です。退会済みの顧客の情報も含まれます。ログインに必要なパスワードや暗証番号など、取引に必要な情報の漏えいは確認されておらず、本件に起因するとみられる不正アクセスや不正取引も、発表時点では確認していません。影響を受けた顧客の特定は完了しており、該当者には個別に連絡するとしています。原因と詳しい経緯は調査中です。

## Optimizelyの脆弱性を悪用したサプライチェーン攻撃、178組織のサイトがマルウェア配信
ウェブサイト最適化サービス「Optimizely」において、Experimentationアカウントの登録処理の脆弱性が悪用され、同社のスクリプトを利用する178の組織のウェブサイトに悪意あるJavaScriptが混入しました。攻撃は11月16日に行われ、調査した1,611件のOptimizelyスクリプトのうち188件に悪意あるコードが含まれていました。影響を受けた組織にはBBC、CNN、Zoom、Salesforce、GitLab、IKEA、HSBC、Equifax、Ledgerなどが含まれます。混入したコードは、訪問者の暗号資産ウォレットアドレスを攻撃者のものに書き換え、決済フォームに入力されたクレジットカード情報をスキミングし、認証クッキーやスクリーンショットを窃取し、iPhoneやiPadの訪問者にエクスプロイトキットを配信するものでした。Optimizelyは脆弱性を修正し、混入したコードを除去し、影響を受けた顧客に直接連絡したとしています。11月16日21時52分（UTC）時点で、悪意あるコードが残っていたのはTalkTalkの1件のみでした。攻撃者のウォレットには約7,000ドル相当の暗号資産が送金されたことが確認されています。なお、各組織自身のサーバーが侵害されたわけではなく、信頼して読み込んでいた共有スクリプトが改ざんされた点が本件の本質です。

## 「Java4Shell」（CVE-2026-114938）の技術詳細が公開、未認証RCEで主要製品に影響
セキュリティ企業Califは11月17日、OpenJDKおよびOracle Java SEの重大な脆弱性「Java4Shell」（CVE-2026-114938）の技術詳細を公開しました。脆弱性は、HotSpot JVMがBase64デコードを高速化するために使う手書きのアセンブリコード（AVX-512 VBMI命令）にあり、特定の入力によりヒープの範囲外書き込みが発生します。影響を受けるのはx86-64 CPUでAVX-512 VBMIに対応する環境で稼働するOpenJDK 17.0.6以降（17、21、25、27）およびOracle Java SE 8 Enterprise Performance Packで、ARM64は影響を受けません。Califは、Jira、Confluence、Jenkins、Keycloak、JFrog Artifactory、PingFederateのデフォルト構成で認証前のリモートコード実行を確認したとしています。CVSS 4.0で9.2（Critical）、OracleのCVSS 3.1では8.1と評価されています。Oracleは11月17日のクリティカルパッチアップデートで修正版（17.0.21.1、21.0.13.1、25.0.5.1、27.0.1.1など）を提供しました。野外での悪用や公開されたエクスプロイトは、発表時点で報告されていません。

## 深掘り

###  「本番でない環境」に本物のデータがある
####  1. テスト環境が本番データを抱える構造
楽天証券の事案で漏えいしたおそれがあるのは、本番の取引システムではなくテスト環境のデータでした。テスト環境は新機能や修正を本番に出す前に動作を確かめる場所ですが、検証の都合で本物の顧客データが置かれることがあります。本番と同等の保護がされていない環境に本番データがある場合、その環境が実質的な本番になります。テスト用データのマスキングや、本番データの持ち込みを原則禁止とする運用が問われます。

####  2. 区分を分けて読む
楽天証券の公表は、漏えいしたおそれのある情報を2区分に分けています。ログインIDのみの区分（最大約1,125万口座）と、住所・出金先口座・年収・資産情報まで含む区分（最大約447万口座）です。2つの数字は扱うデータ項目が異なるため合算できません。公表を読む際は、件数が何を数えているかと、確定か可能性かを分けて見る必要があります。パスワードや暗証番号の漏えいが確認されていない点も、被害の読み方の要点です。

###  信頼して読み込む共有スクリプトの危うさ
####  1. 自社の脆弱性がなくても被害を受ける
Optimizelyの事案では、178の組織のうち各組織自身のサーバーが侵害されたわけではありません。サイトが信頼して読み込んでいた共有スクリプトが改ざんされ、訪問者のブラウザ上で正規スクリプトと同等の権限で悪意あるコードが実行されました。タグマネージャーやA/Bテストツールのようなサードパーティスクリプトは、サイト運営者の管理外でサイトの信頼境界を広げています。

####  2. 検知と遮断の仕組み
対策としては、Content Security Policy（CSP）やSubresource Integrity（SRI）による外部スクリプトの改ざん検知・遮断、依存する外部スクリプトの棚卸しと利用の最小化が挙げられます。Optimizelyの事案では、攻撃は11月16日中にほぼ除去されましたが、除去までに訪問者の決済情報や認証情報が窃取された可能性は残ります。

###  ランタイム自体の欠陥と広範なパッチ運用
####  1. ライブラリではなくランタイムの欠陥
Java4Shellは、アプリケーションやライブラリではなく、Javaランタイム自体のBase64デコーダーにあります。影響を受けるのは、Jira、Confluence、Jenkins、Keycloakなど、Javaで書かれた広く使われる製品群です。ランタイムの欠陥は、依存関係の棚卸しでは拾えず、JavaのバージョンとCPUの組み合わせで影響が決まります。

####  2. パッチの適用順序
Oracleは11月17日に修正版を提供しました。影響を受ける製品のうち、インターネットに公開されているものから優先して適用し、暫定策としてBase64の高速化命令を無効化する設定も検討できます。野外での悪用は報告されていませんが、技術詳細が公開されたことで、悪用の試みが増える可能性があります。

###  関連知識

####  用語解説
*  **サプライチェーン攻撃**：標的そのものではなく、標的が信頼する供給者や共有サービスを侵害して被害を広げる攻撃。Optimizelyの事案では、1つのサービスの脆弱性が178の組織のサイトに波及しました。
*  **Magecart型攻撃**：Webサイトの決済フォームなどに悪意あるJavaScriptを埋め込み、入力されたクレジットカード情報や個人情報をリアルタイムに窃取するクライアントサイド攻撃手法。
*  **AVX-512 VBMI**：x86-64 CPUの命令セット拡張。Java4Shellは、この命令を使ったBase64デコードの高速化コードに存在します。ARM64は影響を受けません。
*  **テスト環境**：新機能や修正を本番に出す前に動作を確かめるための環境。本番のシステムとは別に置かれますが、本物のデータが置かれることがあります。

####  今後の展望
*  **テスト環境のデータ管理の見直し**：
   楽天証券の事案を受け、金融機関をはじめとする企業で、テスト環境に本番データを持ち込む運用の見直しと、データのマスキングやアクセス制限の強化が進むと考えられます。
*  **サードパーティスクリプトの管理強化**：
   Optimizelyの事案を受け、サイト運営者は依存する外部スクリプトの棚卸しと、CSP・SRIによる改ざん検知の導入を進めると考えられます。
*  **Javaランタイムのパッチ適用**：
   Java4Shellの技術詳細が公開されたことで、Java製品を運用する組織は修正版へのアップデートを急ぐと考えられます。

## 結論
2026年11月17日のセキュリティ環境は、楽天証券のテスト環境からの顧客情報漏えい、Optimizelyのサプライチェーン攻撃、Javaランタイムの重大な脆弱性の公開と、信頼の境界が崩れた1日でした。
企業や組織のCISOおよびIT担当者は、テスト環境に本番データを持ち込まない運用の徹底、依存する外部スクリプトの棚卸しと改ざん検知の導入、Java製品の修正版への速やかなアップデートを断行すべきです。
