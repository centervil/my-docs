# CISM (Certified Information Security Manager) 30日間学習計画
## ～情報セキュリティをビジネスリスクの視点で管理する、マネジメント思考を30日で体得する～

本計画は、ISACA認定のCISM（Certified Information Security Manager）試験の4つのドメイン（情報セキュリティガバナンス、情報リスクマネジメント、情報セキュリティプログラム、インシデント管理）を網羅します。単なる暗記ではなく、「CISOとして経営陣に説明し、組織全体のセキュリティを戦略的に管理する」という実務視点を重視します。

<course_context>
CISMの学習は、以下の4つのドメインを軸に構成されています。
1. 情報セキュリティガバナンス (Information Security Governance): 組織のビジネス目標に整合したセキュリティ戦略の策定、ポリシー・標準・手順の体系、経営陣へのコミュニケーション。
2. 情報リスクマネジメント (Information Risk Management): リスクの特定・分析・評価・対応、リスクアペタイトとリスク許容度の定義、リスク指標（KRI）の設計。
3. 情報セキュリティプログラムの開発と管理 (Information Security Program Development and Management): セキュリティコントロールの設計、ベンダー管理、セキュリティ意識向上トレーニング、セキュリティアーキテクチャ。
4. インシデント管理 (Incident Management): インシデントの検出・分類・封じ込め・根絶・復旧・教訓、BCP/DRとの連携、フォレンジック調査。
</course_context>

<day_plans>
<day n="1">
テーマ: CISMの全体像とガバナンスの基礎
内容:
- CISMの4ドメインの位置づけと相互関係を俯瞰する。ISACAの倫理規定を確認する。
- 情報セキュリティガバナンスの定義：「経営層の指示のもと、セキュリティ目標をビジネス目標に整合させる活動」を理解する。
- 思考タスク: 自組織の情報セキュリティ担当者が「技術者」として振る舞っているか「マネージャー」として振る舞っているか、現状を評価する。
</day>

<day n="2">
テーマ: セキュリティ戦略の策定
内容:
- ビジネス戦略と情報セキュリティ戦略の整合（アラインメント）の方法論を学ぶ。
- セキュリティロードマップの作成：短期・中期・長期の目標設定とマイルストーン管理。
- 実践: 自組織（または架空の中堅企業）の「3年間情報セキュリティ戦略ロードマップ」の骨子（目標・KPI・主要施策3つ）を1枚で作成する。
</day>

<day n="3">
テーマ: セキュリティポリシー体系の設計
内容:
- ポリシー・標準・ガイドライン・手順（Procedure）の4層構造とそれぞれの役割の違い。
- 情報セキュリティポリシーに含めるべき必須要素（適用範囲、責任、例外処理、違反時の対応）。
- 思考タスク: 自組織のセキュリティポリシーを入手し、CISM基準に照らして「欠落している要素Top 3」を特定する。
</day>

<day n="4">
テーマ: セキュリティ組織とガバナンス構造
内容:
- CISO・セキュリティ委員会・情報オーナー・情報管理者・ユーザーの責任分担モデル。
- ステアリングコミッティの役割と、経営陣へのセキュリティ報告の方法（メトリクスの選び方）。
- 実践: CISOとして取締役会に提示する「四半期セキュリティ報告書」のアジェンダ（5項目）を設計し、各項目で何を伝えるかを定義する。
</day>

<day n="5">
テーマ: セキュリティフレームワークと標準
内容:
- ISO/IEC 27001・NIST CSF・CIS Controls・COBITの特徴と用途の違いを理解する。
- フレームワーク選択の判断基準（業種・規制要件・組織規模・成熟度）。
- 思考タスク: 自組織が採用すべきセキュリティフレームワークを1つ選び、その選択理由を「経営陣向けの3段落の説明文」として作成する。
</day>

<day n="6">
テーマ: セキュリティメトリクスとパフォーマンス測定
内容:
- KPI（Key Performance Indicator）とKRI（Key Risk Indicator）の違いと設計方法。
- セキュリティプログラムの成熟度モデル（CMM、ISO/IEC 27004）の活用方法。
- 実践: 「パッチ適用率」「インシデント平均検出時間（MTTD）」「フィッシング訓練クリック率」を用いて、ダッシュボード形式のKPI報告書を設計する。
</day>

<day n="7">
テーマ: リスクマネジメントの基礎概念
内容:
- リスクの定義：脅威（Threat）× 脆弱性（Vulnerability）× 資産価値（Asset Value）の関係。
- リスクの種類：固有リスク（Inherent Risk）、残留リスク（Residual Risk）、コントロールリスク。
- 思考タスク: 自組織の「最も重要な情報資産Top 3」を定義し、それぞれに対する主要な脅威を2つずつ列挙する。
</day>

<day n="8">
テーマ: リスクアセスメント手法
内容:
- 定量的リスク分析（ALE = ALE = ARO × SLE）と定性的リスク分析（高・中・低）の使い分け。
- リスクアセスメントの手順：スコーピング→資産識別→脅威・脆弱性分析→リスク評価→報告。
- 実践: 「社員がフィッシングメールをクリックしてランサムウェアに感染するリスク」を定量的に分析し、ALEを計算する（ARO=0.3、SLE=5,000万円と仮定）。
</day>

<day n="9">
テーマ: リスクアペタイトとリスク対応戦略
内容:
- リスクアペタイト（Risk Appetite）とリスク許容度（Risk Tolerance）の定義と経営陣への説明方法。
- リスク対応の4戦略：回避（Avoid）・軽減（Mitigate）・移転（Transfer）・受容（Accept）の選択基準。
- 思考タスク: 「クラウドサービスの利用に伴うデータ漏洩リスク」に対して、4つの対応戦略それぞれの具体的な施策例を考える。
</day>

<day n="10">
テーマ: ビジネスインパクト分析（BIA）
内容:
- BIA（Business Impact Analysis）の目的と手順：重要業務の特定→依存システムの特定→RTO/RPO設定。
- RTO（Recovery Time Objective）とRPO（Recovery Point Objective）の定義と設定の考え方。
- 実践: 架空の金融機関を想定し、「ネットバンキングシステム障害」のBIAを実施する（財務的影響・風評影響・規制上の影響を評価する）。
</day>

<day n="11">
テーマ: サードパーティリスク管理
内容:
- ベンダーリスクアセスメントの実施方法：選定前評価・契約時・継続的モニタリングの3段階。
- セキュリティ要件を契約に盛り込む方法：SLA、右監査条項、データ処理契約（DPA）。
- 思考タスク: 主要ベンダー（例：クラウドサービス、給与計算システム）のリスク評価チェックリスト（10項目）を作成する。
</day>

<day n="12">
テーマ: 規制・法令コンプライアンス
内容:
- 主要な規制・法令の概要：GDPR・個人情報保護法・PCI DSS・SOC 2・医療情報保護（HIPAA）。
- コンプライアンスとセキュリティの違い：「コンプライアンスは最低基準、セキュリティはリスクベース」という考え方。
- 実践: 自組織が準拠すべき規制を3つ特定し、それぞれで求められる「最も重要なコントロール」を1つずつ定義する。
</day>

<day n="13">
テーマ: セキュリティプログラムの設計と構築
内容:
- セキュリティプログラムを構成する要素：ポリシー・技術的コントロール・人的コントロール・物理的コントロール。
- コントロールの種類：予防（Preventive）・検知（Detective）・是正（Corrective）・抑止（Deterrent）の分類と配置設計。
- 思考タスク: 「内部者による不正アクセス」シナリオに対して、予防・検知・是正それぞれのコントロールを2つずつ設計する。
</day>

<day n="14">
テーマ: セキュリティアーキテクチャと多層防御
内容:
- ゼロトラストアーキテクチャ（ZTA）の原則：「決して信頼するな、常に検証せよ」の実装アプローチ。
- 多層防御（Defense in Depth）の設計：ネットワーク・ホスト・アプリケーション・データ各層のコントロール。
- 実践: ハイブリッドクラウド環境（オンプレ＋AWS）を持つ組織のゼロトラスト移行ロードマップを設計する（3段階、各段階の主要施策を定義する）。
</day>

<day n="15">
テーマ: セキュリティ意識向上プログラム
内容:
- セキュリティトレーニングとセキュリティ意識向上（Awareness）の違いと目的の使い分け。
- フィッシングシミュレーション、eLearning、定期訓練などのプログラム設計と効果測定方法。
- 思考タスク: 「フィッシングクリック率を6ヶ月で30%→5%に下げる」という目標を達成するための意識向上プログラムを月次計画で設計する。
</day>

<day n="16">
テーマ: 脆弱性管理プログラム
内容:
- 脆弱性管理のライフサイクル：スキャン→優先順位付け（CVSS/EPSS）→修正→検証→報告。
- パッチ管理プロセスの設計：緊急・高・中・低の重大度に応じた対応期限（SLA）の設定。
- 実践: 「CVSS 9.8のゼロデイ脆弱性が公表された」シナリオでの緊急対応プロセスを24時間タイムラインで作成する。
</day>

<day n="17">
テーマ: アクセス管理とID管理
内容:
- ID管理のライフサイクル：プロビジョニング→アクセスレビュー→デプロビジョニングの管理。
- 特権アクセス管理（PAM）：特権アカウントのリスクと、Just-in-Time（JIT）アクセスの考え方。
- 思考タスク: 「退職した元従業員のアカウントが3ヶ月間有効なままだった」インシデントを防ぐための、人事連携プロセスを設計する。
</day>

<day n="18">
テーマ: データ分類とデータ保護
内容:
- データ分類体系の設計：機密・社外秘・公開などの分類と各分類に対するハンドリング要件。
- 暗号化・マスキング・トークナイゼーションのユースケースと選択基準。
- 実践: 架空の医療機関のデータを「患者の診療記録・請求情報・匿名化研究データ・公開広報資料」に分類し、各分類のハンドリング要件表を作成する。
</day>

<day n="19">
テーマ: セキュリティ運用の管理（SOCとSIEM）
内容:
- SOC（Security Operations Center）の機能モデル：L1/L2/L3アナリストの役割と運用設計。
- SIEM（Security Information and Event Management）の活用：ユースケース設計と誤検知の管理。
- 思考タスク: 社内SOCを設立する際の「CISOとしての意思決定事項Top 5」（人員・ツール・シフト・アウトソース比率等）を整理する。
</day>

<day n="20">
テーマ: インシデント管理の基礎
内容:
- インシデント管理の6フェーズ：準備→識別→封じ込め→根絶→復旧→教訓（NIST SP 800-61準拠）。
- イベントとインシデントの違い、インシデントの分類（重大度レベルの定義）。
- 実践: 「社員のPCがマルウェアに感染した」インシデントを題材に、識別から封じ込めまでのステップをチェックリスト形式で作成する。
</day>

<day n="21">
テーマ: インシデントレスポンス計画（IRP）の設計
内容:
- IRPに含めるべき要素：目的・スコープ・役割と責任（RACI）・通知手順・エスカレーション基準。
- インシデントコマンドシステム（ICS）の構造とCISOの役割。
- 思考タスク: 「重大なデータ漏洩が発覚した」場合の最初の72時間における、CISOとしての意思決定フローを時系列で作成する。
</day>

<day n="22">
テーマ: フォレンジック調査と証拠保全
内容:
- デジタルフォレンジックの原則：証拠の完全性保持（チェーン・オブ・カストディ）と収集順序（揮発性の高いものから）。
- ログ分析・メモリフォレンジック・ネットワークフォレンジックの概要と証拠価値。
- 実践: 「内部犯行の疑いがある従業員のPCを調査する」シナリオで、法的に有効な証拠として採用されるための証拠収集手順書を作成する。
</day>

<day n="23">
テーマ: BCP（事業継続計画）とDR（災害復旧）
内容:
- BCPとDRの違い：BCPは「業務継続」、DRは「システム復旧」の計画であることを理解する。
- DR戦略の種類：ホットサイト・ウォームサイト・コールドサイトの比較とRTO/RPOへの影響。
- 思考タスク: 自組織の基幹システムについて、「ホットスタンバイ構成」と「クラウドへのレプリケーション」を比較し、コストとRTOのトレードオフを経営陣向けに説明する資料を設計する。
</day>

<day n="24">
テーマ: BCP・DRテストとメンテナンス
内容:
- BCPテストの種類：机上演習（Tabletop）・ウォークスルー・シミュレーション・フルテストの特徴と目的。
- BCP/DRの維持管理サイクル：年次レビュー・変更管理との連携・訓練結果のフィードバック。
- 実践: 「主要データセンターが突然停電した」シナリオの机上演習を設計する（目的・参加者・シナリオ・評価基準を定義する）。
</day>

<day n="25">
テーマ: クラウドセキュリティのガバナンス
内容:
- クラウド責任共有モデルをCISMの観点から解釈する：リスクとガバナンスの観点での責任分担。
- クラウドセキュリティ評価：CSA STAR認証・SOC 2 Type IIレポートの読み方と活用方法。
- 思考タスク: 自組織がSaaS（例：Salesforce）を導入する際のリスクアセスメント項目（データ主権・可用性・サードパーティ監査・解約時のデータ返却）を評価する。
</day>

<day n="26">
テーマ: プロジェクトにおけるセキュリティの組込み（DevSecOps）
内容:
- セキュリティ・バイ・デザイン：システム開発ライフサイクル（SDLC）の各フェーズへのセキュリティ統合。
- DevSecOpsにおけるCISMの役割：セキュリティ要件定義・脅威モデリング・コードレビュー・本番前チェックの仕組み化。
- 実践: 新しいモバイルアプリ開発プロジェクトに対して、CISOとしてSDLCの各フェーズで「承認ゲート（Security Gate）」を設ける場所と基準を設計する。
</day>

<day n="27">
テーマ: 情報セキュリティ調達と契約管理
内容:
- セキュリティ製品・サービス調達時の評価基準：機能要件・セキュリティ要件・ベンダー信頼性。
- SLA（Service Level Agreement）にセキュリティ要件を組み込む方法とKPIの測定方法。
- 思考タスク: 「SIEM製品の更新（リプレイス）」を検討する際に、CISOとして調達委員会に提示すべき評価基準マトリクスを作成する（機能・セキュリティ・コスト・ベンダー実績・移行容易性の5軸）。
</day>

<day n="28">
テーマ: セキュリティ文化と組織変革管理
内容:
- セキュリティ文化の醸成：「罰則によるコンプライアンス強制」から「理解に基づく行動変容」への転換方法。
- 経営陣・管理職・一般従業員への異なるアプローチとコミュニケーション戦略。
- 実践: 「セキュリティを企業文化に根付かせるための1年間のキャンペーン計画」を四半期ごとの主要テーマと活動（3つ）で設計する。
</day>

<day n="29">
テーマ: 試験対策 - ドメイン横断の事例問題演習
内容:
- CISMの問題形式の特徴：「CISMとして最初に何をすべきか」「最も適切な行動は何か」という設問への回答技術。
- よく問われる状況別の優先行動パターン（リスクの特定 → 経営陣への報告 → 対策の実施の順序）を整理する。
- 実践: ISACA公式問題集または模擬試験を1セット（150問）解き、誤答した問題をドメイン別に分類して弱点ドメインを特定する。
</day>

<day n="30">
テーマ: CISMとしての実務への還元と継続的改善
内容:
- 30日間の学習を振り返り、「自組織のセキュリティガバナンスの成熟度」を5段階で自己評価する。
- 実践: 自組織のセキュリティプログラムの改善提案を「経営層向けの1ページ報告書」としてまとめる（現状評価・最重要リスク2つ・推奨アクション・投資対効果の4構成）。
</day>
</day_plans>
