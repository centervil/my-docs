## 📚 今日の学習テーマ：データ流出（Data Exfiltration）対策

### 📝 学習の目標

* データ流出の典型的な攻撃経路（S3、ECR、Lambda等）を理解し、そのリスクを特定する。
* Amazon MacieやGuardDutyを活用した、機密データ検出および異常検知の仕組みを習得する。
* 内部犯行者によるデータ持ち出しを想定した多層的な防御・検知コントロールを設計する。

### 🔍 カバーする範囲

本日はAWS環境におけるデータ流出対策に焦点を当てます。S3バケットの誤設定や、コンテナイメージ・環境変数を通じた情報漏洩のリスクを整理し、それらを検知・防御するためのAWSネイティブなツール（Macie、GuardDuty）の活用方法を学習します。

## 📖 解説パート

### データ流出の主要な攻撃経路

AWS環境において、データ流出は主に設定ミスや不適切なアクセス制御から発生します。代表的な経路は以下の通りです。

1. **S3バケットのパブリック公開**: 最も一般的なリスクです。バケットポリシーやACLの誤設定により、インターネット全域から機密データが閲覧可能となります。
2. **ECRイメージへの機密情報埋め込み**: コンテナイメージのビルド時にAPIキーや認証情報をハードコードしてしまうケースです。イメージが外部に公開された場合、情報が漏洩します。
3. **Lambda環境変数**: Lambda関数の環境変数に認証情報や機密情報を平文で保存するケースです。関数へのアクセス権限を持つ攻撃者によって、これらの情報が抽出されるリスクがあります。

これらの経路を塞ぐには、最小権限の原則に基づくIAM管理と、自動化された設定監査が不可欠です。

### 検知のためのAWSセキュリティツール

データ流出を未然に防ぐだけでなく、発生を即座に検知する仕組みが必要です。

* **Amazon Macie**: S3バケットを継続的にスキャンし、PII（個人情報）などの機密データを自動的に発見・分類します。意図しない場所に機密データが配置された場合にアラートを上げます。
* **GuardDuty (S3 Protection)**: S3に対する異常なAPIリクエスト（通常とは異なるIPからの大量ダウンロードや、不審なアクセスパターン）を機械学習によって検知します。

```bash
# S3 Protectionを有効化するコマンド例
aws guardduty update-detector --detector-id <detector-id> --features '[{"Name": "S3_DATA_EVENTS", "Status": "ENABLED"}]'
```

#### 重要ポイント

* S3のブロックパブリックアクセス（BPA）設定を組織レベルで強制する。
* コンテナイメージやコード内の機密情報は、Secrets ManagerやParameter Storeを使用して動的に取得する。
* Macieの結果をEventBridge経由で通知し、インシデント対応チームに即時エスカレーションする。

## 🏢 ケーススタディ

### ケース：悪意ある内部犯行者によるS3からのデータ持ち出し

権限を持つ従業員が、退職直前にS3バケット内の顧客リストを自身の個人アカウントへコピーしようと試みるシナリオ。当該ユーザーは正規のアクセス権を持っており、セキュリティグループ等の境界防御をすり抜けてアクセスします。

#### 問題点

* 正規の認証情報を使用しているため、通常のアクセスログでは悪意の判別が困難。
* 大量のデータダウンロードが短時間で行われると、ビジネスへの影響が出るまで気づかない可能性がある。
* 持ち出し先のS3バケットがAWS外部または別のアカウントである場合、追跡が困難。

#### 対応策

* **GuardDuty S3 Protection**: 異常なデータアクセスパターンを検知しアラートを発報。
* **CloudTrailログの監視**: 普段の業務時間外や、大量のGetObject呼び出しを監視するアラートの設定。
* **VPCエンドポイントポリシー**: S3へのアクセスを自社のアカウントIDに限定する制限をかける。
* **IAM条件キー（aws:SourceVpce）**: VPC内からのアクセスのみを許可する。

#### ケースから学ぶ教訓

* 内部犯行は「権限の悪用」が前提となるため、アクセス制御だけでなく「行動の異常検知」が重要。
* ログの取得は必須だが、ログを見るだけでは不十分であり、自動化された監視ツールとの組み合わせが不可欠。

## 📋 今日のまとめ

* データ流出は、S3の公開設定やハードコードされた認証情報など、基本的な設定不備から発生することが多い。
* Amazon Macieで機密データの所在を可視化し、GuardDutyで異常なアクセスパターンを検知する多層防御を構築する。
* 内部犯行対策には、VPCエンドポイントポリシーなどのネットワーク境界による制限と、異常検知の仕組みを組み合わせる。
